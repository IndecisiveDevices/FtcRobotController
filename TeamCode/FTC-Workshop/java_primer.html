Big Idea

Java is picky because robots are picky

When we program a robot, Java needs exact instructions. A human might understand “drive the thingy forward,” but a robot needs clear names, symbols, and spelling.

Think of Java code like build instructions for a robot pit crew. If one part name is wrong, the crew grabs the wrong part. If one instruction is missing, the robot brain pauses and asks for better punctuation.

Java is case sensitive

Java treats uppercase and lowercase letters as different characters. That means leftPower, LeftPower, and leftpower are three different names.

Works? Example Why?
✅ Yes leftPower Matches the variable name exactly.
❌ No LeftPower The first letter changed to uppercase.
❌ No leftpower The capital P disappeared.

Semicolons: Java’s stop signs

Why use them? A semicolon tells Java, “This instruction is finished.” Without it, Java keeps looking for more and gets confused. That is why many Java commands end with ;.

frontLeftDrive.setPower(leftPower);

That line is one complete instruction: send leftPower to the front-left motor.

Curly brackets: code rooms

Curly brackets create “rooms” for code. A class has a room. Each method has its own smaller room inside the class. Code that belongs to a method must be typed inside that method’s brackets.

Curly brackets also hold decision code, like if and else. That is Java’s way of saying, “If this is true, do this. Otherwise, do that.”

if (leftPower > 0) { // Do this when leftPower is forward } else { // Do this when leftPower is not forward }

Why no semicolon after brackets?

A semicolon ends one complete instruction. A curly bracket starts or ends a block of code, so Java does not need a semicolon right after it.

public class TankDriveExample { }

Semicolon rule of thumb

Use a semicolon after a complete command:

double speed = 0.5;

Do not use one when opening a block with { or closing a block with }

Variables: labeled boxes for robot information

Why use them? Robots need to remember information while they run. A variable gives a value a name so we can use it later. In tank drive, variables store joystick power before sending that power to the motors.

The word double means the box stores a number that can have decimals, like 0.5, 1.0, or -0.25.

double leftPower = -gamepad1.left_stick_y; double rightPower = -gamepad1.right_stick_y;

Translation: “Make two number boxes. Put the left joystick value in one box and the right joystick value in the other.”

Robot memory moment

A variable is not magic. It is a name tag on a value. Instead of saying, “use whatever number came from the left joystick,” we say leftPower.

Classes: the robot program’s blueprint

A class is the big container for a Java program. For FTC, your TeleOp code lives inside a class. The class name should match the file name so Android Studio can find everything neatly.

public class TankDriveExample extends OpMode { }

The curly brackets mark the beginning and end of the class. Everything for this robot program goes between them.

Code nesting map

class └── method └── instructions

Class is the big robot garage. Methods are workbenches. Instructions are the tools on each bench.

Methods: named jobs inside the class

A method is a named chunk of code that does a job. You can think of a method like a button on a robot control panel. When that method runs, the instructions inside it happen.

public void sayRobotReady() { telemetry.addData("Status", "Robot Ready!"); }

The method above has a name: sayRobotReady. The instructions inside the curly brackets belong to that method.

FTC special methods

In FTC TeleOp programs, two special methods are required by the FTC SDK:

  • init() runs once when the robot is getting ready.
  • loop() repeats while the robot is active.

These are not random Java words. They are part of how FTC robot programs work.
